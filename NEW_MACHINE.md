# Setting up a new machine to match the Zanskar work Mac

These are instructions for Claude Code (or a human) to reproduce the terminal
setup from Jake's work Mac. They were written on 2026-09-03 by inspecting that
machine. Read the whole file before running anything: the "What broke before"
section explains why the install script does several odd-looking things.

The repo is PUBLIC (github.com/jcallahan4/dotfiles). Never commit tokens,
keys, or Zanskar-internal material to it. See "Deliberately not in this repo".

## 2. What this repo contains and where each piece is linked

`install.sh` creates these links. The home-directory paths are what the tools read.

| Repo path | Installed as | Notes |
|---|---|---|
| `zsh/zshrc_common` + `zsh/zshrc_<type>` | sourced by a 2-line `~/.zshrc` that `install.sh` writes | `<type>` is `work`, `personal`, or `hpc`, chosen at install time |
| `zsh/p10k.zsh` | `~/.p10k.zsh` (symlink) | Powerlevel10k "pure" style, generated by `p10k configure` |
| `wezterm/wezterm.lua` | `~/.wezterm.lua` (symlink) | |
| `config/nvim/*` | `~/.config/nvim/*` (one symlink per entry) | per-entry so the gitignored `lazy-lock.json` can be a real local file |
| `config/karabiner/` | copied (not linked) to `~/.config/karabiner/` only if no config exists | Karabiner rewrites its own file and may replace a symlink |
| `config/alacritty/` | `~/.config/alacritty/` | legacy from the personal Mac; Alacritty is not installed on the work Mac; the themes submodule is not initialized |
| `latex/` | `$TEXMFHOME/tex/latex/dotfiles` (symlink) | TEXMFHOME comes from `kpsewhich`; only runs if TeX is installed |
| `claude/CLAUDE.md` | `~/.claude/CLAUDE.md` (symlink) | global Claude Code instructions |
| `claude/output-styles/plain-teacher.md` | `~/.claude/output-styles/plain-teacher.md` (symlink) | |
| `Brewfile` | not installed automatically | full `brew bundle dump` of the work Mac, including work-only software |

`install.sh` also: backs up anything it replaces into `~/.dotfiles_backup/<timestamp>/`,
installs the core packages per OS, appends the Homebrew `shellenv` line to
`~/.zprofile` on macOS, and on Linux makes bash hand off to zsh (see section 7).

## 3. Things only the human can do first

Claude cannot do these. Ask for them before starting if they are missing.

1. **SSH keys and the `github-personal` alias.** The repo remote is
   `git@github-personal:jcallahan4/dotfiles.git`. On the work Mac, `~/.ssh/config`
   has a `Host github-personal` entry pointing at `github.com` with the personal
   key (the key files are `id_ed25519_personal` / `.pub`). There is a separate
   work key `id_ed25519_zsk` for Zanskar repos, which use plain `github.com`.
   Copy the keys over securely (not through this repo) and add the alias.
   Test with `ssh -T git@github-personal` and expect "Hi jcallahan4!".
2. **Homebrew** on macOS (https://brew.sh). `install.sh` exits if `brew` is missing.
3. **Interactive logins**, done after the install: `gh auth login`, `gcloud auth login`,
   `gcloud auth application-default login`, `cliproxyapi --claude-login`,
   `cliproxyapi --codex-login`, and Karabiner-Elements' input-monitoring permission
   in System Settings.

## 4. Steps on macOS

Run these in order. Each step says what to check. Where a step produces a lot
of output, tee it to a log under `/tmp` (per the global CLAUDE.md) so the human
can `tail -f` it.

1. Clone and set the personal git identity for this repo only (the global
   identity on the work Mac is the Zanskar one):
   ```bash
   git clone git@github-personal:jcallahan4/dotfiles.git ~/dotfiles
   cd ~/dotfiles
   git config user.name "Jake"
   git config user.email "jcallahan4@gmail.com"
   ```
2. Run the installer. It is interactive: it asks `personal/work/hpc`. Answer
   `work` for a Zanskar machine. It installs zsh, neovim, zoxide, powerlevel10k,
   tree-sitter, the two zsh plugins, the Meslo Nerd Font, and WezTerm, then
   creates all the links from section 2.
   ```bash
   ./install.sh
   ```
   Check: `cat ~/.zshrc` shows the two `source` lines; `ls -la ~/.p10k.zsh
   ~/.wezterm.lua ~/.config/nvim` shows symlinks into `~/dotfiles`;
   `grep shellenv ~/.zprofile` finds the Homebrew line.
3. Open a new WezTerm window. The prompt should be the Powerlevel10k "pure"
   style with Nerd Font icons. If icons are boxes, the font did not install:
   `brew install --cask font-meslo-lg-nerd-font`, then restart WezTerm.
4. Neovim. Plugins install on first start. Do it headless so Claude can see the output:
   ```bash
   nvim --headless "+Lazy! sync" +qa
   nvim --headless -c "MasonToolsInstallSync" -c qa
   nvim --headless -c "lua require('nvim-treesitter').install({'json','javascript','typescript','tsx','yaml','html','css','prisma','markdown','markdown_inline','svelte','graphql','bash','lua','vim','dockerfile','gitignore','query','vimdoc','c','python'}):wait(300000)" -c qa
   ```
   Mason installs pyright through npm, so `node` must exist first
   (`brew install node`). The treesitter step needs the `tree-sitter` CLI on
   PATH (`brew install tree-sitter`; the installer already does this).
   Check: `ls ~/.local/share/nvim/site/parser` lists about 21 `.so` files;
   `ls ~/.local/share/nvim/mason/packages` lists lua-language-server, pyright,
   html-lsp, stylua, ruff, latexindent.
5. Linting and formatting helpers that Mason does not manage:
   ```bash
   npm install -g eslint_d
   ```
   `prettier` is expected per-project (it is not installed globally on the work Mac).
6. Keyboard: `brew install --cask karabiner-elements`, open it once, grant the
   permissions it asks for. `install.sh` already copied `karabiner.json` into
   place if there was none. Check in Karabiner-EventViewer that Caps Lock
   produces Escape.
7. Claude Code:
   ```bash
   curl -fsSL https://claude.ai/install.sh | bash
   ```
   It installs to `~/.local/bin/claude`, which `zshrc_work` already puts on PATH.
   Then restore the user settings. `~/.claude/CLAUDE.md` and the output style
   are already linked by `install.sh`. In `~/.claude/settings.json` set (or use
   `/config` for the ones it exposes):
   - `"model": "claude-fable-5-1[1m]"`
   - `"outputStyle": "Plain Teacher"`
   - `"effortLevel": "xhigh"` and `"modelSettings": {"claude-fable-5-1": {"effortLevel": "high"}}`
   - `"permissions": {"defaultMode": "auto"}`
   - `"attribution": {"commit": "", "pr": ""}` (no Claude trailer on commits)
   - `"theme": "auto"`, `"autoCompactEnabled": true`, `"fileCheckpointingEnabled": true`
   Do not copy the old `settings.json` wholesale: its hooks contain absolute
   `/Users/jacob.c/...` paths that the autoresearch installer generates.
8. Claude Code skills. Install fresh rather than copying, then start a new session:
   ```bash
   npx skills add uditgoenka/autoresearch   # writes hooks, /autoresearch commands, and the skill
   npx skills add nutlope/hallmark          # lands in ~/.agents/skills; copy to ~/.claude/skills if not picked up
   ```
   On the work Mac the hallmark skill had to be copied by hand:
   `cp -r ~/.agents/skills/hallmark ~/.claude/skills`.
   The `zanskar-design` skill is Zanskar brand material and is NOT in this
   repo. Copy `~/.claude/skills/zanskar-design/` from the work Mac over a
   private channel (it was also copied into `~/.codex/skills` there).
9. Python tooling:
   ```bash
   curl -LsSf https://astral.sh/uv/install.sh | sh
   uv python install 3.10 3.12
   uv tool install keyring --with keyrings.google-artifactregistry-auth   # work: pip/uv auth to Google Artifact Registry
   ```
10. TeX (optional, needed for vimtex and the `mathdoc` class):
    ```bash
    brew install --cask mactex-no-gui
    ```
    Then re-run the TEXMFHOME block at the bottom of `install.sh` (or the whole
    installer) so `~/Library/texmf/tex/latex/dotfiles` gets linked. vimtex is
    configured to use Skim as the viewer; Skim was installed by hand on the
    work Mac (`brew install --cask skim` works). For LaTeX in PowerPoint:
    `brew tap tsung-ju/iguanatexmac && brew install --cask iguanatexmac latexit-metadata`.
11. Work-only tools (skip on a personal machine):
    ```bash
    brew install gh tree fd pnpm rclone
    brew install --cask gcloud-cli docker-desktop fuse-t codex
    brew install cliproxyapi && brew services start cliproxyapi
    ```
    `cliproxyapi` is what the `claudex` alias in `zshrc_work` talks to: it runs
    Claude Code against a `gpt-5.6-sol` model through a local proxy after
    `cliproxyapi --claude-login` and `cliproxyapi --codex-login`. Its config in
    `/opt/homebrew/etc/cliproxyapi.conf` and the OAuth files in
    `~/.cli-proxy-api/` are per-machine secrets; do not copy them into the repo.
    gcloud on the work Mac was set up with `gcloud auth login`,
    `gcloud auth application-default login`, and
    `gcloud auth application-default set-quota-project zanskar-prod`.
    Alternatively install the entire inventory: `brew bundle --file=~/dotfiles/Brewfile`.

## 5. Steps on a Linux VM (GCP, Ubuntu 22.04, OS Login)

`install.sh` handles Linux with apt. Answer `work` at the prompt. What it does
differently, and why, is in section 7. After it finishes, log out and back in:
bash execs zsh on interactive login. Then do step 4 (Neovim), step 7 (Claude

## 7. What broke before, and what had to change (read this)

These are the fixes made while getting the work Mac and the Linux VM working.
Most are encoded in `install.sh` and the zsh files; the notes explain why.

1. **Neovim 0.12 broke nvim-treesitter.** The `master` branch of
   nvim-treesitter does not support Neovim 0.12+. The config was ported to the
   rewritten `main` branch: the `ensure_installed` table became an explicit
   `require('nvim-treesitter').install({...})` call, highlighting is started
   per buffer with `vim.treesitter.start`, incremental selection (removed
   upstream) was reimplemented by hand in `treesitter.lua`, and nvim-ts-autotag
   is set up standalone. Do not switch the branch back.
2. **The `main` branch needs the `tree-sitter` CLI** to compile parsers (the
   old branch only needed a C compiler). macOS: `brew install tree-sitter`.
   Ubuntu 22.04: the prebuilt GitHub release binaries need a newer glibc than
   22.04 ships, so `install.sh` builds it with `cargo install tree-sitter-cli`
   (installing rustup, clang, and libclang-dev first) and links it into
   `/usr/local/bin`. On the work Mac there is also an npm-global
   `tree-sitter-cli`; it is redundant with the Homebrew one.
3. **Node had to be new enough for pyright.** Mason installs pyright through
   npm and pyright needs Node 14+. Ubuntu's apt `nodejs` is v12 and pyright
   misbehaves silently. `install.sh` purges apt node and installs the current
   LTS tarball into `/opt/node` (the LTS version is read from nodejs.org's
   `index.json`; an earlier hardcoded version was wrong, see commit "fixed node
   version in install script"). macOS uses Homebrew node.
4. **apt's Neovim is too old.** `install.sh` downloads the official stable
   tarball into `/opt/nvim` and links `/usr/local/bin/nvim`.
5. **`chsh` does not work on GCP OS Login VMs.** The account is served through
   NSS and is not in `/etc/passwd`, so there is nothing for `chsh` to edit.
   `install.sh` instead appends a guarded block to `~/.bashrc` that `exec zsh -l`
   for interactive shells only (guards prevent it running for scp/scripts and
   prevent loops once in zsh).
6. **TEXMFHOME differs by OS.** macOS (MacTeX) uses `~/Library/texmf`, Linux
   TeX Live uses `~/texmf`. An early version hardcoded `~/texmf`, which left a
   stray, harmless `~/texmf/tex/latex/dotfiles` link on the Mac. The installer
   now asks `kpsewhich -var-value=TEXMFHOME`. No `mktexlsr` is needed; TeX
   searches `tex/latex` live.
7. **Powerlevel10k lives in three different places.** Intel Homebrew:
   `/usr/local/share/powerlevel10k`; Apple Silicon Homebrew:
   `/opt/homebrew/share/powerlevel10k`; Linux: git clone into
   `~/.local/share/powerlevel10k`. `zshrc_work` loops over the candidates.
   `zshrc_personal` still hardcodes the Intel path and a
   `/Users/jakecallahan/miniforge3` conda install; if you set up the personal
   Mac, check those paths first.
8. **zsh plugins likewise.** Homebrew puts them under `$(brew --prefix)/share`,
   apt under `/usr/share`. `zshrc_common` loops over both.
9. **`~/.local/bin` had to be on PATH.** Both uv and the Claude Code native
   installer put binaries there. `zshrc_work` exports it.
10. **Homebrew was not on PATH in new shells.** The `eval "$(brew shellenv)"`
    line was added to `~/.zprofile` by hand on the work Mac; `install.sh` now
    writes it.
11. **The p10k, WezTerm, Karabiner, and Claude configs were not in the repo**
    until 2026-09-03. They were plain files in `$HOME`. They are now tracked and
    linked (Karabiner is copied, see section 2).
12. **Per-entry nvim symlinks** exist so `lazy-lock.json` (gitignored) can be
    a real file in `~/.config/nvim`. A side effect is that the tracked junk files
    `config/nvim/test.*` (a LaTeX test build) also get linked. Safe to delete
    from the repo when convenient. Because the lockfile is ignored, plugin
    versions are not pinned across machines; if something breaks on the new
    machine, compare against the work Mac's `~/.config/nvim/lazy-lock.json`.
13. **MacTeX.** The full `mactex` cask was installed first, then swapped for
    `mactex-no-gui`. Install `mactex-no-gui` directly.
14. **Docker.** `brew install docker` installs only the CLI formula; it was
    uninstalled and replaced with the cask (`docker-desktop`).
15. **Two GitHub accounts.** `gh` is logged into `jcall42` (work, active) and
    `jcallahan4` (personal). This repo uses the `github-personal` SSH alias and a
    repo-local personal git identity so commits are not attributed to the work
    address.
16. **Global gitignore.** `~/.config/git/ignore` on the work Mac ignores
    `**/.claude/settings.local.json`. That file is machine-local, so the same
    pattern is now in this repo's `.gitignore` too.
17. **Claude Code hooks use absolute paths.** `~/.claude/settings.json` on the
    work Mac has autoresearch hooks pointing at `/Users/jacob.c/.claude/hooks/...`.
    On a machine with a different username, reinstall autoresearch instead of
    copying settings.
18. **zoxide "configuration issue" warning inside Claude Code.** Claude Code's
    Bash tool runs commands in a snapshot of the shell that does not restore
    zsh's `precmd_functions`, so every `cd` (aliased to `z`) prints a zoxide
    doctor warning there. A real interactive terminal does not show it. To
    silence it, `export _ZO_DOCTOR=0` in `zshrc_work`.
19. **Karabiner-Elements and Skim were installed by hand** (not through
    Homebrew) on the work Mac. Use the casks on a new machine.
20. **The autoresearch privacy hook blocks commands that mention log paths
    under `/tmp`.** This conflicts with the global CLAUDE.md instruction to tee
    output there. If a command is refused with "denied by .ckignore", write the
    file with the Write tool or log somewhere else.

## 8. Deliberately not in this repo

- `~/.ssh/*` (keys, config with the `github-personal` alias).
- `~/.npmrc` and `~/.yarnrc.yml`: they hold a Google Artifact Registry access
  token for the `zanskar-prod` npm registry (`us-central1-npm.pkg.dev`). Those
  tokens are `gcloud` access tokens and expire; regenerate with gcloud on the new
  machine. Never commit them.
- `~/.config/gcloud`, `~/.config/gh`, `~/.cli-proxy-api/*.json`,
  `/opt/homebrew/etc/cliproxyapi.conf`: credentials.
- `~/.claude/skills/zanskar-design/`: company brand material.
- `~/.claude/settings.json`: machine-specific hook paths (key values listed in section 4, step 7).
- `~/.config/nvim/lazy-lock.json`: gitignored by choice (see item 12 above).
- `~/.gitconfig`: holds the work identity (`Jake Callahan <jacob.c@zanskar.us>`); set per machine.
